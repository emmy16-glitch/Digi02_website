# Digi02 Design Source of Truth

**Status: LOCKED / APPROVED BASELINE**

This directory is the permanent design specification for the Digi02 website. Implementation work must reference these files before changing page structure, brand colors, component language, image direction, responsive behavior, or QA expectations.

## Change control

Do not materially change the approved design during implementation unless all three steps happen first:

1. The proposed change is discussed and approved.
2. The relevant document in this directory is updated.
3. The implementation is then changed to match the updated document.

No implementation task may silently override the blueprint because a different layout, image, card style, or color feels easier to code.

## Files

- `DIGI02-DESIGN-SYSTEM.md` — brand, color, typography, surfaces, cards, navigation, motion and reusable component rules.
- `DIGI02-PAGE-BLUEPRINT.md` — exact page-by-page section sequence and purpose.
- `DIGI02-ASSET-RULES.md` — hard rules for imagery, screenshots, product visuals and decorative graphics.
- `DIGI02-RESPONSIVE-RULES.md` — required desktop, tablet and mobile behavior.
- `DIGI02-QA-CHECKLIST.md` — mandatory pre-merge and post-merge verification.
- `reference-index.md` — how the supplied design references should influence Digi02 without copying their branding or assets.

## Non-negotiable brand identity

Digi02 remains Digi02. The redesign may borrow layout systems, spacing, hierarchy and interaction patterns from references, but it must retain:

- the Digi02 logo;
- Digi02's real content, team, projects, products and Kaduna/Africa identity;
- black / warm-white / gold branding;
- an editorial + operational + technological tone;
- high-quality, purpose-built visuals rather than reference screenshots used as production artwork.
